# J2.5 Hybrid Black-Box Investigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend J2.5 so the local model chooses each investigation step while bounded code gathers evidence, attempts authorized tests, verifies distinct information-bearing findings, and reports measured black-box performance.

**Architecture:** Keep `J25Runner` as the decision loop and `J25Actions` inside the isolated browser worker. Extend observed references and fixed actions; keep raw requests and credentials private to the worker. A deterministic evidence reducer and a separate benchmark oracle classify outcomes, while the model's hypotheses remain unverified text.

**Tech Stack:** Python 3, existing Playwright/BrowserHTTP, FastAPI dashboard, unittest, local Ollama; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-j25-blackbox-design.md`

## Global Constraints

- Preserve J1, J2, v4 and old J2.5 records; retain the current dirty worktree and run data.
- Authorized same-origin targets only. State-changing tests require explicit isolated/recoverable test identity and scope; GET may also change state.
- No generated Python/shell, remote provider by default, secret-bearing model context/report, or Juice Shop answer hardcoding.
- 50% is an illustration, never a pass/stop threshold. Maximize uniquely verified findings within budget.
- Real-target total prevalence is unknown unless independently registered; report its rate as unmeasurable.
- Benchmark default: preregister at least 20 unique eligible cases over four categories, hold out at least 10 over three, each category two or more and no category over half; repeat the final set three times from reset state. Record ineligible cases and reasons separately.
- Screen/browser and full regression checks follow `AGENTS.md` and the user's existing explicit test requests. Do not commit the user's dirty tree.

## Review Focus

- A previously visible ref disappears between model decision and execution: reject before sending a request and keep prior evidence (Task 2 test).
- A reflected benign value or HTTP 500 differs from baseline: retain candidate but never count verified information gain (Task 5 test).
- A POST captured during a real form flow includes cookies and a token: only the private worker may replay it; redact both from logs/context (Task 3 test).
- A lab oracle fails immediately before reset: preserve unknown verdict, still stop worker and reset lab (Task 6 test).
- A final benchmark includes a supported but unattempted active case: keep it in the denominator with zero credit (Task 7 test).
