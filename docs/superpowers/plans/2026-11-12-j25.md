# J2.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan. Steps use checkbox syntax for tracking.

**Goal:** Give a local model short investigation decisions while fixed code performs observations and comparisons.

**Architecture:** A J2.5 runner connects the existing model transport and budgets to typed browser-worker actions. A worker-owned registry keeps exact GET requests and URLs in memory, exposing bounded references and observations to the runner and deterministic report.

**Tech Stack:** Existing Python, unittest, Playwright worker and model transports.

**Spec:** `docs/superpowers/specs/2026-11-12-j25-design.md`.

## Global Constraints

- Preserve existing uncommitted work, other prompt versions, origin guards, cleanup, output and report reservation.
- Do not run browser/UI verification, live targets/models or the full test suite unless the user explicitly requests them.
- GET comparisons only; retain query secrets in worker memory, reject stale IDs and ambiguous fields.
- No generated Python or shell code from J2.5 decisions; model claims are unverified.

## Review Focus

- GET query values and credentials must not leak through references, reports or comparison records.
- Worker restart or evicted references cannot select a different request.
- One failed comparison request retains prior stages as partial, never confirmed.
- SPA hash routes must remain distinct, including links beginning `/#/`.
- Model-call, tool-call, stop and report budgets remain effective for automatic work.

## Execution record

- Ruling: work in the existing feature workspace because the approved design builds on its pre-existing uncommitted J2 changes; do not stage or commit those changes.
- Independent review identified navigation status, truncation, cancellation, reference expiry and sensitive query handling issues; focused regressions were added and corrected.
- After the user requested full and live-target verification, the full suite passed 400 tests with 12 opt-in skips. The opt-in Chromium UI suite separately passed all 10 tests. Worker source compiled and JavaScript syntax passed.
- A temporary localhost search fixture ran with Playwright and local `qwen3:4b-instruct` and completed page observation, normal→test→normal GET comparison, report, and cleanup. The comparison had a stable baseline and different test response; this is functional evidence, not vulnerability or discovery-performance evidence. Local `qwen3:8b` also completed the comparison on a fixture with one unvisited link, which correctly left the run incomplete.
- The runtime tests now use portable commands and pass on macOS. The real Juice Shop `v20.2.0` target ran through Chromium with local `qwen3:8b`: J2.5 captured `/rest/products/search?q=`, selected `apple` → `banana` → `apple`, received three HTTP 200 responses, reproduced the `apple` baseline exactly (921 bytes and the same SHA-256), and observed a different `banana` response (277 bytes and a different SHA-256). Cleanup and the final Juice Shop reset succeeded. The run remains intentionally `incomplete` because unrelated discovered references were left unexamined; the response difference is functional evidence, not a vulnerability finding.
- The first Juice Shop attempt exposed a real classification bug: blocked external fonts and the unsupported Socket.IO WebSocket made a successful HTTP 200 page observation incomplete. A regression test now keeps those blocks visible without invalidating the main-document observation. The scripted replay and one live run do not establish discovery performance.
- Follow-up improvements were integrated into J2.5: two identical consecutive failures are temporarily guarded, model context prioritizes actionable references while retaining the full registry, goal assessment is labeled as an unverified model claim separately from coverage, and model calls, decision time, first successful comparison and blocked repeats are saved. Partial comparison samples cannot be scored as a successful comparison.
- A subsequent Juice Shop run with local `qwen3:8b` again reached a stable apple → banana → apple comparison in two tool steps. It recorded three model calls, 50.512 seconds of model-decision time, goal status `completed` (model assessment), coverage `partial`, and successful cleanup/reset. One model call still proposed an already-observed page; the existing guard rejected it and the next call selected the search comparison. One run cannot establish a general model-performance improvement or verify security conclusions.
- After the final context-compaction and legacy-assessment corrections, the Python suite ran 410 tests successfully with two environment-specific skips, including the opt-in Chromium UI scenarios. All 15 Node tests passed; the real Juice Shop run preceded those final two targeted corrections, which have separate regression tests.
