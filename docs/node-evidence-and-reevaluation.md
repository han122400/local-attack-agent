# 노드 증거와 조사 후 재평가

발견 항목의 `observations`는 해당 입력에서 측정한 사실만 담는다. 선택 필드
`discovered[].evidence_refs`는 같은 결과의 최상위 `evidence_refs`에 등록한 파일 중
그 발견을 뒷받침하는 파일을 지정한다. 없는 파일 참조는 결과 계약에서 거절한다.
명시적인 빈 배열은 증거 없음이며, 필드가 없는 과거 기록은 기존 부모 시도 증거
조회 방식과 호환된다. 새 결과에서 귀속이 생략되면 빈 배열로 정규화하며,
새 프롬프트는 각 발견에 이 필드를 명시하도록 지시한다.

현재 조사 중인 표면과 위치·메서드·입력·인증 문맥이 같은 명시적 후보는 누락된
관찰값과 증거 참조를 현재 결과에서 보완할 수 있다. 루트나 다른 위치의 발견에는
이 보완을 적용하지 않는다. 증거 파일은 로컬에 보존하며 JEV에는 허용된 범주형
관찰만 전송한다. 토큰, 응답 원문, 파일 경로, 자유 서술은 JEV 입력에 넣지 않는다.

관찰의 선택 필드 `baseline_status`는 기준 요청 상태, `response_status`는 시험 요청
상태이다. `security_signal`은 `unknown`, `auth_bypass`, `weak_credentials`,
`account_enumeration`, `query_injection`, `unescaped_reflection`, `cross_user_access`
중 하나이다. 이 필드는 실행 모델이 증거를 해석한 단서이며 독립 검증 결과가 아니다.
생략된 새 필드는 과거 점수 입력의 해시가 바뀌지 않도록 기본값으로 추가하지 않는다.

성공한 표면 조사에 증거·기준 비교·입력 제어·구체적인 보안 단서와 이를 뒷받침하는
관찰이 있으면 누락된 후속 후보를 최대 1개 생성한다. 인증 결과는 인증 후보,
쿼리 단서는 SQLi 후보 등으로 연결하며 후보가 다시 자동 후보를 생성하지 않는다.
일반적인 500 오류, 정상 자기 계정 로그인, 모델의 `confirmed` 주장만으로는 생성하지
않는다. 생성 정책은 새 결과 이벤트에 기록하고 원본 모델 결과 파일은 보존한다.
과거 이벤트를 재생할 때 후보를 소급 생성하지 않는다.

후속 후보는 별도 조사 대상으로 실행되고 후보 요약에 나타난다. 조사 후 평가는
완료한 형제 노드도 포함하되 완료 노드를 다시 탐색 대상으로 선택하지 않는다.
이전 점수와 이력을 보존하며, 관찰이 바뀌면 이전 점수는 `stale`로 표시한다.
관찰이 기존 맥락으로 돌아오면 캐시된 점수 상태를 복원한다.

호출·시간·비용 예산은 재평가에도 적용된다. 부모별 호출 한도가 2회 이상이면
탐색 중에는 마지막 재평가용 호출 1회를 남긴다. 부모별 누적 호출 한도에 도달하면
`parent_limit` 사유와 이전 점수를 보존하며 최신 평가로 취급하지 않는다.
후속 후보나 높은 점수가 취약점 확정을 뜻하지 않으며 자동 확정 판정은 제공하지 않는다.
