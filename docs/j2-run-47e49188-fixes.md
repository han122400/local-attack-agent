# 저장된 J2 실행 오류 수정

대상 기록: `47e491889cc0424c91fbfa4ca8b52543`. 원본 로그·코드·응답은 변경하지 않았다.
요청에 따라 실제 대상·모델을 다시 실행하지 않고 로컬 코드와 모의 결과로만 확인했다.

## 확인한 원인

33단계 중 성공 출력 10개, 실패 23개였다.

| 실패 원인 | 원본 건수 | 수정 |
| --- | ---: | --- |
| 존재하지 않는 tools 모듈에서 제공 도우미 import | 13 | 생성 코드 실행 안에서 제공 도구 import 지원 |
| browser 모듈 import | 2 | 제공 브라우저 객체 import 지원, 이어서 발생할 page.get_text 오용 사전 안내 |
| 미설치 requests import | 5 | 실패에서 확인한 미설치 모듈을 다음 호출에도 유지하고 기존 도구·표준 라이브러리 사용 안내 |
| http_get을 모듈로 import | 1 | 함수와 모듈을 구분하는 구체적인 사전 오류 안내 |
| 누락된 await | 1 | 기존 사전 검사 유지 |
| 실행 시간 초과 | 1 | 기존 시간 한도·부분 출력 보존 유지 |

이외에 형식 오류 7회가 모델 호출을 사용했다. 마지막 CALL-0040은 보고서를 실제 생성했지만
본문을 content에 넣어서 거절됐다. 이제 실행 입력이 섞이지 않은 finish의 보고서 본문은 기존
reason과 함께 보존한다. 마지막 호출의 제공자 출력 스키마도 finish만 허용하도록 좁혔다.
원본 마지막 응답을 새 정규화·검증 함수에 통과시켜 본문 보존을 확인했으며 새 모델 호출은 0회였다.

성공한 GET 단계도 2,000자 본문만으로 전체 HTML·JS 분석을 시도했다. J2의 http_get 본문 상한을
200만 자로 바꾸고 잘림 표시를 유지했다. 기존 버전의 2,000자 기본값과 origin 제한은 유지했다.
추가 HTTP 요청이나 자동 응답 저장은 추가하지 않았다.

## 해석 범위

잘못된 Page API와 http_get 반환값의 속성 접근을 실행 전에 안내한다. 브라우저 API 정보도 정확한
호출 형태·반환 형태·본문 상한이 보이도록 제공한다. tools/browser import 지원은 실행 코드의
지역 import 처리에만 적용하고 전역 sys.modules나 설치 라이브러리를 바꾸지 않는다.

보고서를 복구해도 실패와 후보 추적 부재가 있으면 조사 미완료로 남긴다. 원래 보고서의 보안
주장은 독립적으로 검증하지 않았고, 특히 마지막 cart 요청은 import 단계에서 실패해 실행되지 않았다.
정적 응답 확보를 공격 성공이나 안전성 입증으로 계산하지 않는다.

확인한 것은 로컬 재현·정규화·워커 대역·제공자 요청 변환이다. 실제 재실행의 실패율·탐지율·점수는
측정하지 않았다. requests/bs4 등의 새 의존성을 설치하지 않았다.
