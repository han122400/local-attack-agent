# J2 하네스 개선 기록 · 2026-11-07

목표는 실제 발견·재현 성과이며 `scorecard.py` 가중치나 완료 기준을 완화하지 않았다.
작업 시작 시점의 J2가 포함된 작업 폴더를 기준으로 정보 유실과 재실행 낭비를 재현했다.
저장된 종료 실행 8개 중 도구를 사용한 6개의 단계는 총 168개, 실패·시간 초과는 37개다.
이 과거 기록에는 J2 실실행이 없으므로 이 수치를 J2의 실패율로 해석하지 않는다.

## 확인하고 수정한 부분

| 병목 | 변경 | 확인한 범위 |
| --- | --- | --- |
| 긴 출력이 65,536자에서 앞부분만 남음 | 같은 길이 안에서 앞뒤와 생략 표시 보존 | 마지막 관측이 남고 전체 출력 로그도 유지됨 |
| 큰 파일을 조용히 잘라 읽음 | 앞뒤 미리보기와 `output_truncated` 전달 | 원본 파일은 그대로이며 마지막 관측·잘림 표시 확인 |
| 코드 뒷부분만 보여 복구 시 초기 설정을 잃음 | 코드 앞뒤와 원본 경로 보존 | 변수 설정·실패 지점과 읽을 수 있는 상대 경로 확인 |
| 최근 두 단계 밖의 작업 코드를 다시 찾기 어려움 | 단계 이력에도 `source_path` 추가 | 세 번째 작업 후 첫 코드 경로 유지 |
| 동기 `captured_requests()`를 await해 앞선 작업 후 실패 | 동기 도우미 오용을 실행 전 검사 | 실제 보존 코드 두 건에서 이전 미검출→검출, 로컬 재정의 허용 |
| 정책 비교 시 실제 지침과 저장 해시가 다름 | 생성자에 지침·해시를 명시해 전달 | 모의 전송 지침이 정책별로 다르고 기록 해시와 일치 |

전후 오프라인 관측은 [JSON 기록](evidence/j2-harness-regressions-2026-11-07.json)에 남겼다.
새 공격 페이로드, 강제 유형 순서, 고정 횟수 후 후보 포기, 자동 HTTP 수집은 추가하지 않았다.

## 검증과 다음 측정

원본을 직접 수정하지 않은 임시 실행 폴더, 모의 전송, 실제 보존 코드의 정적 검사로 확인했다.
원본 코드나 로그가 존재한다는 사실은 입력 처리나 보안 영향의 독립 확인이 아니다.
큰 파일의 중간은 여전히 생략하므로 필요한 경우 원본의 관련 구간을 명시적으로 읽어야 한다.

다음 실제 비교에서는 같은 대상 초기 상태·목표·실행 모델·예산으로 J1/J2를 반복 실행하고,
실제 입력 처리 확인, 대조군이 있는 후보 시험, 독립적으로 재현되는 보안 영향과 미완료·실패·비용을
따로 판독해야 한다. 현재 파일 참조 비교기는 웹 취약점 성공률을 평가하지 않는다.
`--prompt-version`으로 실제 전송할 프롬프트를 고정할 수 있지만, 대상·모델 실험은 아직 실행하지 않았다.

브라우저 실행·대상 접속·실모델·전체 테스트는 수행하지 않았다. 탐지율 향상 수치를 주장하지 않는다.
