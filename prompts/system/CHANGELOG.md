# 시스템 프롬프트 변경 기록

기본 적용 버전: **v2** (`planning.py`의 `SYSTEM_PROMPT_VERSION`). 대시보드에서 실행별 버전을 선택할 수 있습니다.
이 번호는 시스템 프롬프트에만 해당하며, 탐색 설계 문서의 v4와는 별개입니다.

## 실행 관찰과 요청 재사용 — 2026-10-27

- 브라우저의 같은 origin POST 등 일반 HTTP 메서드를 허용하고 외부 요청·WebSocket 차단 이유를
  실행 결과와 모델 이력에 전달합니다. 브라우저가 차단한 로그인 요청을 사이트 오류로 오인하지 않도록 했습니다.
- 기존 `http_get`에 헤더·본문 잘림 여부·바이너리 메타데이터를 추가했습니다. 별도 응답 수집기나
  전체 응답 저장은 추가하지 않았습니다.
- 실제 브라우저 폼 요청을 최근 8개까지 메모리에 보관하고, 숨김 필드·본문 형식을 유지한 명시적 재전송을
  지원합니다. 현재 쿠키를 사용하며 토큰 만료나 HTTP 성공을 자동 판단하지 않습니다.
- 실패·타임아웃의 부분 출력을 이력과 보고서에 보존합니다. 성공 단계와 구분하며, 반복 관찰 판정에도 섞지 않습니다.
- 정의되지 않은 `main()`과 실제 발생했던 Playwright API 오용을 실행 전에 검사합니다. 정상 메서드 참조·
  병렬 await·변수 재사용을 잘못 막지 않도록 검사 범위를 제한했습니다.
- 새 도구 안내의 중복을 줄이고, 입력 예산이 부족할 때 기준 코드의 선택적 요청 설명을 줄입니다.
  목표·단계 참조·코드 경로·해시와 실제 요청 재사용 ID는 보존합니다.
- 관련 검증은 가짜 요청·응답·워커를 사용한 단위 테스트이며, 실제 브라우저나 대상 사이트를 실행하지 않습니다.

## J1 보고 지침 조정 — 2026-10-27

- 특정 취약점 유형의 언급을 강제하던 규칙을 삭제했습니다. 실제 관찰로 유망한 후보가 생겼거나
  직접 시도한 항목만 보고하며, 미시도 유형은 보고서 목차에 자동으로 넣지 않습니다.
  코드가 만드는 보고서도 `not_started` 항목을 제외합니다.
- 동일 응답·몇 개 입력의 실패·404·반사 미발견·잘린 출력으로 취약점 부재나 방어 성공을 단정하지
  않도록 했습니다. 결과는 실제 시험한 경로·입력·맥락에 한정하고, 조사 중단과 안전성 입증을 구분합니다.
- 유형별 필수 목록 대신 관찰된 기능과 실제 후보를 중심으로 보고하며, 후보의 유망성은 구체적인
  관찰 근거가 필요한 가설로 표시합니다. 실제 출력과 계획을 구분하고 실패 단계의 유효한 부분 관찰도 보존하도록 했습니다.

## 공통 실행 제어 — 2026-10-27

- 마지막 모델 호출의 보고 예약을 v1·v2·J1에 공통 적용했습니다. 이전에는 J1만 호출 잔량을 기준으로
  보고 단계로 전환해 v1·v2가 마지막 호출도 탐색에 사용할 수 있었습니다.
- 기본 40회와 사용자 지정 50·60회 모두 실제 설정값을 기준으로 마지막 1회를 예약합니다.
  보고 단계에서는 `finish`만 허용하며, 형식 수정 재시도도 보고 예약을 소비하지 못합니다.
  보고 실패 시 추가 호출 없이 저장된 관찰로 보고서를 만듭니다. 도구 한도에 도달해도 보고 호출은 가능합니다.
- 프롬프트 원문은 변경하지 않았습니다. 호출 한도·재시도·보고 강제·API 설정 전달을 관련 단위 테스트로 확인합니다.

## J1 — 2026-10-26

- `J1.txt`를 추가했습니다. v1·v2 원문과 기본 선택 v2는 유지합니다. 서버를 재시작하고
  새 실험의 시스템 프롬프트에서 **J1**을 선택해야 아래 제어가 적용됩니다.
- v2의 범위·비신뢰 데이터·근거 분리·사용자 언어 규칙과 v1·v2의 실행 도우미 안내를 유지합니다.
  기존 Command JSON 형식도 유지합니다. `plan`의 `SQLi/baseline: 설명` 같은 단계 표기는 선택 사항입니다.
- 검토 과정에서 발견한 SQLi → IDOR → XSS 고정 순서와 전 항목 완료 전 종료 차단을 제거했습니다.
  실제 관찰과 권한·대조군·검증 비용을 근거로 후보를 선택합니다. 다른 유형도 먼저 조사할 수 있습니다.
  정상 기준·비교·필요한 재검증을 추적합니다. 단계 표기나 `reason`의 `[step:N]` 참조가 없거나
  맞지 않는 명령도 실행하며, 해당 단계는 후보 진행에 반영하지 않고 `unlinked_steps`와
  `advisories`에 기록합니다. 참조와 순서 검사는 HTTP 진위나 의미상 적합성을 독립 검증하지 않습니다.
- 아직 조사하지 않은 항목은 `not_started`와 미평가 사유를 유지합니다. 후보가 관찰됐지만 계정·권한 등
  전제가 없으면 `blocked`로 기록합니다. 모든 항목에 시도 또는 blocked 표시를 강제하지 않습니다.
  같은 코드 오류 세 번으로 전체 유형을 자동 중단하던 휴리스틱도 제거했습니다. 오류는 미검증 사유로 남습니다.
- 기준 단계 번호를 후보 식별자로 사용하고 후보별 진행 상태를 보존합니다. 같은 유형의 두 입력을 번갈아
  조사할 수 있으며, 서로 다른 후보의 기준·비교 단계가 섞이면 거부합니다. `coverage`는 최근 요약,
  `candidates`는 후보별 기록입니다. 최근 4개 후보의 간단한 참조를 모델에 전달합니다.
- 기준 단계에서 정상 종료하고 출력을 남긴 Python 코드의 경로·해시와 정적으로 읽을 수 있는 요청 필드를
  최근 30단계 기록과 별도로 보존합니다(최근 최대 8개). 같은 형식의 새 기준 코드도 별도로 기억합니다.
  비교·검증에서는 해당 후보의 기준 URL·메서드·필드를 비교해 다른 요청이 같은 후보의 진행으로
  기록되지 않게 합니다. 변경된 요청도 실행되며, 의도한 변경인지 확인하도록 안내합니다. 동적 코드와 일부 호출 형식은 필드를
  추출하지 못할 수 있어 원본 코드 참조가 남습니다. 이 기록은 HTTP 성공을 독립적으로 입증하지 않습니다.
  `request(method, url)`·클라이언트 별칭 등 읽을 수 있는 정적 호출도 지원하며 일반 딕셔너리의 `.get()`은
  HTTP 요청으로 취급하지 않습니다. 동적 필드·`**kwargs`·24개 초과 필드는 `null`로 남겨 빈 폼으로 오인하지 않습니다.
- 설정된 모델 호출 한도 안에서 마지막 1회를 최종 보고에 남깁니다.
  탐색 중 내부 재시도도 이 예약분을 소비하지 못합니다. 호출 한도가 1회라면 탐색 없이 보고만 합니다.
  마지막 보고 실패 시 추가 호출을 쓰지 않고 보존 상태로 보고합니다. 시간·도구 한도는 더 이른 보고를
  유발할 수 있습니다. 모델 보고 실패·시간 초과·중단에도 단계와 미검증 사유를 포함한 보고서를 만듭니다.
- 일시적 통신 오류가 탐색 재시도 한도에 닿아도 보고 예약을 사용할 수 있도록 재시도 가능 여부를 전달합니다.
  인증·잔액 오류는 보고를 위해 다시 호출하지 않습니다. 명령 타임아웃은 남은 실행 시간 이하로 제한하고,
  취소된 실행은 성공 출력으로 계산하지 않습니다. 오류 복구에 걸린 시간도 종료 시점 추정에 반영합니다.
- 동일한 관찰 요약만으로 새 경로로 전환하라고 지시하지 않습니다. 정상 대조군·재검증의 의도적 반복을
  먼저 구분하도록 했으며, 실제 전환의 탐지 성능 효과는 측정하지 않았습니다.
- J1 컨텍스트에서는 기준 코드 참조·진행 상태를 유지하고 긴 실행 출력과 최근 코드의 미리보기를 줄입니다.
  수정 재시도의 잘못된 응답도 누적하지 않습니다. 문자 예산은 토큰 수의 근사치이며 실제 한도 보장은 아닙니다.
- `j1_state.coverage`의 `reviewed_unverified`는 단계 실행 기록이고, 취약점 확정이나 방어 입증이 아닙니다.
  `completed`도 실행 종료를 뜻합니다. HTTP 증거 수집기나 취약점 자동 확정 기능은 추가하지 않았습니다.
- 관련 단위 테스트로 고정 순서 제거·관찰 참조·요청 필드 보존·보고 예약·입력 압축과 API 선택 전달을 확인했습니다.
  실제 모델의 탐지 성능 향상은 동일 조건의 v1/v2/J1 비교 실험으로 별도 측정해야 합니다.

## v2 — 2026-10-26

- 범위·신뢰 규칙 → 행동 선택 → 증거 판단 → 종료 보고 순서로 정리하고 도구 사용 예시는 뒤로 옮겼습니다.
- 브라우저뿐 아니라 셸·Python도 대상 origin과 세션 작업 폴더의 범위를 따르도록 명시했습니다.
  **이것은 모델의 행동 지침입니다. OS 수준의 네트워크·파일 접근 차단을 추가한 것은 아닙니다.**
- 페이지·HTML·API 응답·파일·로그·명령 출력을 신뢰할 수 없는 데이터로 지정했습니다.
  해당 내용이 실행 이력에 포함되어도 목표나 안전 규칙을 바꾸는 지시로 따르지 않습니다.
- URL 변화 등 입력 실행의 보조 신호와 취약점 증거를 분리했습니다. 정상 입력과 비교하고,
  실제로 확인된 보안 영향을 근거로 판단하도록 했습니다. 단순 오류·반사·결과 수 변화만으로 확정하지 않습니다.
- 일반 `reason`은 실행 전에 쓰므로, 다음 행동을 선택한 이유를 설명하게 했습니다.
  실행 결과는 코드 출력으로 기록하고, 최종 보고는 `finish.reason`에 작성합니다.
- `plan`·`reason`·최종 보고는 사용자가 지정한 언어, 지정이 없으면 목표의 언어를 따릅니다.
  JSON 키·코드·URL·인용 증거는 그대로 유지합니다.
- 최종 보고에는 필요한 근거를 충분히 담을 수 있도록 일반 행동의 짧은 설명 규칙과 구분했습니다.
- 소형 모델에 필요한 await·도우미 함수·절대 URL·SPA 사용 안내는 유지했습니다.

## v1 — 2026-10-26 원문 보관

버전 관리를 도입하기 직전 `planning.py`의 `SYSTEM_PROMPT` 문자열을 그대로 저장했습니다.
이 날짜는 원문 작성일이 아니라 보관일입니다.

## 실행 로그와 이후 수정 방법

- 각 `model_request` 이벤트에 `system_prompt_version`과 `system_prompt_sha256`을 기록합니다.
  해시는 모델에 전달하는 프롬프트 문자열을 UTF-8로 인코딩해 계산한 SHA-256입니다.
- 기존처럼 실제 프롬프트 전문도 `input.messages[0].content`에 남습니다.
  버전과 해시 필드는 로그에만 추가되며 모델 API 요청 형식은 바뀌지 않습니다.
- 이전 실행 로그는 수정하지 않습니다. 버전 표시가 없는 과거 실행은 저장된 프롬프트 전문으로 확인합니다.
- 이후 수정할 때는 기존 버전 파일을 덮어쓰지 말고 `J1.txt`처럼 새 파일을 추가한 뒤 이 기록을 갱신합니다.
  기본 선택까지 바꾸려는 경우에만 `planning.py`의 `SYSTEM_PROMPT_VERSION`을 변경합니다.
  하네스 변경을 포함했다면 해당 프로세스를 다시 시작해야 적용됩니다.
- 과거 문구로 되돌리려면 버전 상수를 `v1` 등으로 변경하고 프로세스를 다시 시작합니다.

v1·v2 원문 정리 당시에는 추가 테스트를 진행하지 않았습니다. J1 검증 범위는 위 J1 항목을 참고하세요.
