# 시스템 프롬프트 변경 기록

현재 적용 버전: **v4** (`planning.py`의 `SYSTEM_PROMPT_VERSION`에서 선택).
이 번호는 시스템 프롬프트에만 해당하며, 탐색 설계 문서의 v4와는 별개입니다.

## v4 — 2026-10-26 로컬 실행 복원

- 사용자 요청에 따라 Docker 코드 격리와 HTTP 중계를 제거하고, main의 로컬 Python·셸·Playwright 실행 방식으로 복원했습니다.
- 실제 세션 작업 경로와 Python 실행 파일을 사용하며, Windows·macOS/Linux에서 WSL 없이 컨트롤러를 실행합니다.
- v2의 범위·신뢰·증거·보고 규칙과 feat/jihun의 `compare_inputs` 안내를 함께 사용합니다.
- 컨테이너 경로·직접 네트워크 차단·컨트롤러 HTTP 증거 ID에 의존한 안내를 현재 프롬프트에서 제거했습니다.
- 이전 버전 파일은 과거 실행 기록 확인을 위해 보존합니다.

## v3 — 2026-10-26 main → feat/jihun 병합

- v2의 범위·신뢰·증거·보고 규칙에 feat/jihun의 Docker 격리 실행과 HTTP 중계 경로 안내를 합쳤습니다.
- 생성 명령은 `/work`를 사용하는 Linux 컨테이너에서 실행되며, 직접 네트워크 연결 대신 컨트롤러의 HTTP 중계와 브라우저 탐색을 사용하도록 명시했습니다.
- 실제 HTTP 증거와 출력·모델 주장을 구분하고, `compare_inputs`의 정상/테스트/정상 비교 안내를 유지했습니다.
- 기존 v1·v2 파일은 보존하며, 실행 로그의 버전과 해시는 실제 적용된 v3를 가리킵니다.

## v2 — 2026-10-26

- 범위·신뢰 규칙 → 행동 선택 → 증거 판단 → 종료 보고 순서로 정리하고 도구 사용 예시는 뒤로 옮겼습니다.
- 브라우저뿐 아니라 셸·Python도 대상 origin과 세션 작업 폴더의 범위를 따르도록 명시했습니다.
  **이것은 모델의 행동 지침입니다. OS 수준의 네트워크·파일 접근 차단을 추가한 것은 아닙니다.**
- 페이지·HTML·API 응답·파일·로그·명령 출력을 신뢰할 수 없는 데이터로 지정했습니다.
  해당 내용이 실행 이력에 포함되어도 목표나 안전 규칙을 바꾸는 지시로 따르지 않습니다.
- URL 변화 등 입력 실행의 보조 신호와 취약점 증거를 분리했습니다. 정상 입력과 비교하고,
  실제로 확인된 보안 영향을 근거로 판단하도록 했습니다. 단순 오류·반사·결과 수 변화만으로 확정하지 않습니다.
- 일반 `reason`은 실행 전에 쓰므로, 다음 행동을 선택한 이유를 설명하게 했습니다.
  실행 결과는 코드 출력으로 기록하고, 최종 보고는 `finish.reason`에 작성합니다.
- `plan`·`reason`·최종 보고는 사용자가 지정한 언어, 지정이 없으면 목표의 언어를 따릅니다.
  JSON 키·코드·URL·인용 증거는 그대로 유지합니다.
- 최종 보고에는 필요한 근거를 충분히 담을 수 있도록 일반 행동의 짧은 설명 규칙과 구분했습니다.
- 소형 모델에 필요한 await·도우미 함수·절대 URL·SPA 사용 안내는 유지했습니다.

## v1 — 2026-10-26 원문 보관

버전 관리를 도입하기 직전 `planning.py`의 `SYSTEM_PROMPT` 문자열을 그대로 저장했습니다.
이 날짜는 원문 작성일이 아니라 보관일입니다.

## 실행 로그와 이후 수정 방법

- 각 `model_request` 이벤트에 `system_prompt_version`과 `system_prompt_sha256`을 기록합니다.
  해시는 모델에 전달하는 프롬프트 문자열을 UTF-8로 인코딩해 계산한 SHA-256입니다.
- 기존처럼 실제 프롬프트 전문도 `input.messages[0].content`에 남습니다.
  버전과 해시 필드는 로그에만 추가되며 모델 API 요청 형식은 바뀌지 않습니다.
- 이전 실행 로그는 수정하지 않습니다. 버전 표시가 없는 과거 실행은 저장된 프롬프트 전문으로 확인합니다.
- 이후 수정할 때는 기존 버전 파일을 덮어쓰지 말고 `v3.txt`처럼 새 파일을 추가한 뒤,
  `planning.py`의 `SYSTEM_PROMPT_VERSION`과 이 기록을 갱신합니다. 해당 프로세스를 다시 시작해야 적용됩니다.
- 과거 문구로 되돌리려면 버전 상수를 `v1` 등으로 변경하고 프로세스를 다시 시작합니다.

이번 변경 후 추가 테스트는 사용자 요청에 따라 진행하지 않았습니다.
