# Local Attack Agent

로컬 Ollama 또는 OpenRouter API 모델이 OWASP Juice Shop의 화면과 네트워크 관찰을 바탕으로 탐색 계획과 다음 행동을 선택하는 실험 프로젝트입니다. FastAPI 대시보드에서 계획, 모델 출력, 관찰 기록, 가설과 응답 비교 결과를 확인할 수 있습니다.

기본 대상은 `http://127.0.0.1:3000/`의 Juice Shop입니다. 새 실험 화면에서 본인이 소유하거나 탐색 권한이 있는 사이트의 HTTP(S) URL을 직접 입력하고, 설정 저장 버튼으로 다음 방문에도 유지할 수 있습니다. 각 실험의 Playwright 페이지 요청과 기본 HTTP 도우미는 선택한 대상의 origin으로 제한됩니다. Juice Shop이 아닌 대상은 연결을 선확인하거나 자동 초기화하지 않습니다. 응답 차이는 관찰 결과로 기록하며 취약점 확정을 의미하지 않습니다.
브라우저는 같은 origin의 일반 HTTP 메서드(GET·HEAD·OPTIONS·POST·PUT·PATCH·DELETE)를 허용하고
WebSocket 연결과 외부 origin 요청은 차단합니다. 상태 변경은 사용자가 허용한 목표·범위를 따라야 합니다. 실행은 최대 10분이며,
응답 본문 수집은 최대 8초입니다. 수집 실패 응답은 오류로 기록하고 실험 후보에서 제외합니다.

## 실행 환경

- Python 3.10 이상
- Docker Desktop
- Ollama 및 설치된 로컬 모델 또는 OpenRouter API 키
- Playwright Chromium

## 시작하기

프로젝트 폴더에서 Python 의존성과 브라우저를 설치합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

macOS/Linux에서는 다음 명령을 사용합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
```

Juice Shop 실습 컨테이너를 준비합니다.

```powershell
docker pull bkimminich/juice-shop:v20.2.0
docker run -d --name juice-lab -p 127.0.0.1:3000:3000 bkimminich/juice-shop:v20.2.0
```

컨테이너가 이미 있다면 `docker start juice-lab`으로 시작합니다. Ollama를 실행하고 `ollama list`에 모델이 있는지 확인한 뒤 대시보드를 시작합니다.

```powershell
.\.venv\Scripts\python.exe app.py
```

macOS/Linux에서는 `.venv/bin/python app.py`로 시작합니다.

테스트는 Windows에서 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`,
macOS/Linux에서 `.venv/bin/python -m unittest discover -s tests -v`로 실행합니다.
브라우저 테스트에는 위에서 설치한 Chromium이 필요하며, 모델 응답과 사이트는 모의 데이터로 검증합니다.

브라우저에서 <http://127.0.0.1:8765/>에 접속해 설치된 모델을 선택합니다. Ollama 연결 주소는 `http://127.0.0.1:11434`입니다.

### OpenRouter 모델 사용

프로젝트 루트의 `.env`에 키를 직접 입력합니다. 형식은 `.env.example`을 참고하세요.

```dotenv
OPENROUTER_API_KEY=여기에_발급받은_키
```

의존성을 설치한 뒤 서버를 재시작하고, 새 실험 화면에서 **모델 제공자 → OpenRouter API**를 선택합니다.
API에서 조회한 텍스트 생성 모델 중 하나를 선택해 실행할 수 있습니다. Ollama를 실행하지 않아도 됩니다.
키를 수정한 경우 모델 목록의 **새로고침**을 누르면 다시 읽습니다. 같은 이름의 프로세스 환경변수가 있으면 `.env`보다 우선합니다.

목표, 관찰 내용, 코드와 실행 결과가 OpenRouter 및 해당 모델 제공자에게 전송되며 모델별 요금이 적용됩니다.
키는 서버의 인증 헤더에만 넣고 API 응답·세션 로그·하위 실행 프로세스 환경에는 넣지 않습니다. `.env`는 Git에서 제외됩니다.

Thinking과 Temperature는 모델이 지원할 때만 적용합니다. 컨텍스트 토큰은 앱의 대화 압축 예산이며
원격 모델의 컨텍스트 크기를 변경하지 않습니다. 출력 토큰은 `max_tokens`로 전달하되,
모델의 한도와 입력 분량 추정치에 따라 상한을 줄입니다. 토크나이저별 실제 입력 한도는 제공자가 최종 검증합니다.
구조화 출력을 지원하는 모델에는 JSON Schema를, JSON 모드만 지원하면 JSON 모드를 요청하며,
그 외 모델도 기존 프롬프트와 명령 검증·재시도 흐름을 사용합니다.
인증 실패, 크레딧 부족, 호출 제한은 화면과 로그에 오류로 표시하며 다른 모델로 자동 전환하지 않습니다.

### 호출 예산과 종료 보고

모델 호출 한도는 기본 40회이며 화면에서 변경한 값을 사용합니다. 모든 프롬프트 버전에서 설정한
호출 예산의 **마지막 1회**를 보고에 예약합니다(50회면 50번째, 60회면 60번째 호출).
탐색 재시도도 예약분을 소비하지 못하며, 보고 호출의 탐색 명령은 실행하지 않습니다. 한도가 1회면 보고만 합니다.
마지막 보고가 실패하면 추가 호출 없이 저장된 관찰로 보고서를 만듭니다. 시간·도구 예산이 먼저 부족하면
더 일찍 보고하며, 모델이 충분한 결과를 얻었을 때도 조기 종료할 수 있습니다.

### HTTP 도우미와 요청 재사용

- 기존 `http_get`은 상태·헤더·본문 미리보기와 `body_truncated`·`binary`를 반환합니다. 본문은 최대
  2,000자이며, 전체 텍스트가 필요하면 `get_text`를 사용합니다. 바이너리를 텍스트로 해석하지 않고,
  쿠키 헤더는 값을 가리고 속성을 남깁니다. 별도의 자동 HTTP 응답 수집기나 전체 응답 저장은 추가하지 않았습니다.
- 브라우저가 실제 전송한 최근 폼 요청 8개를 실행 중 메모리에 보관합니다. `captured_requests()`로
  요청 ID와 필드명을 확인하고 `await replay_request(id, fields={"필드명": "새 값"})`로 재사용합니다.
  숨김 필드·본문 형식·프레임워크 헤더를 유지하고 현재 브라우저 쿠키를 사용합니다. 캡처한 인증 헤더는
  보존하므로 실제 신원과 토큰 유효성을 확인해야 합니다. 캡처는 요청 성공이나 취약점의 증거가 아닙니다.
- 재사용은 요청을 다시 전송합니다. 허가된 범위에서만 사용하며, 만료된 토큰은 새 요청을 관찰해 갱신합니다.
  2 MB 초과 본문·파일 내용 변경은 지원하지 않습니다. 요청 본문·쿠키·인증값은 요청 목록에 노출하지 않습니다.
- `blocked_requests`에는 하네스의 차단 이유를 남깁니다. 이를 사이트 오류로 해석하지 않습니다.
  실패·타임아웃 이전에 얻은 출력은 부분 관찰로 보존하며, 전체 실행 성공이나 보안 검증 완료로 계산하지 않습니다.

## 구성

### 시스템 프롬프트 J1

서버를 재시작하고 새 실험 화면의 **시스템 프롬프트 → J1**을 선택합니다.
파일은 `prompts/system/J1.txt`이며 v1·v2 원문과 기본 선택 v2는 유지됩니다.
목표 입력 방식은 같습니다. J1을 선택한 실행에만 다음 제어가 적용됩니다.

- 관찰된 기능·입력·객체·표시 맥락과 권한을 근거로 조사할 후보를 선택합니다. 유형별 고정 순서나
  필수 점검 목록은 없습니다. 보고서에는 관찰 근거가 있는 유망 후보나 실제 시도한 항목만 포함합니다.
  제한된 시험에서 문제가 확인되지 않았다는 결과를 취약점 부재나 안전성 입증으로 표현하지 않습니다.
  `CHECK/STAGE:` 표기와 `reason`의 `[step:N]` 참조는 후보 추적을 돕는 선택 사항입니다. 빠지거나 맞지 않아도
  명령은 실행되며, 해당 단계는 후보 진행에 반영하지 않고 `unlinked_steps`와 `advisories`에 남깁니다.
  코드가 검사하는 것은 참조 존재와 단계 순서이며 HTTP 진위나 후보의 실제 적합성까지 검증하지는 않습니다.
  관찰된 후보의 전제가 없으면 `blocked`, 아직 평가하지 않은 항목은 미평가로 남깁니다. 조기 종료도 가능합니다.
- 기준 단계 번호별로 후보를 분리해 같은 유형의 다른 입력을 조사해도 이전 후보의 진행 상태를 보존합니다.
  `candidate_refs`에서 최근 후보를 참고하고, 해당 후보의 기준·비교 단계 번호로 다시 이어갈 수 있습니다.
- 기준 단계에서 실행된 코드의 경로·해시·읽을 수 있는 요청 필드를 별도로 보존합니다(최근 최대 8개).
  같은 요청 형식이라도 새 기준 코드를 기억해 오래된 토큰·인증 정보를 재사용하지 않도록 합니다.
  비교·검증 중 요청 URL·메서드·필드가 달라지면 안내를 남기되 실행을 막지 않습니다. 의도한 변경도
  보안 판단에 사용할 수 있도록 이유와 실제 응답 차이를 확인해야 합니다.
  동적으로 만든 요청은 필드를 읽지 못할 수 있으며, 코드 실행 성공은 HTTP 성공의 독립 증거가 아닙니다.
  `form_fields: null`은 추출 불가를 의미합니다. 필드가 없는 요청으로 판단해 차단하지 않습니다.

세션의 `j1_state.coverage`는 유형별 최근 요약이며, 전체 후보의 단계·미검증 사유는 `j1_state.candidates`,
최근 기준 코드 참조는 `j1_state.request_memory`에 남습니다. 모델 보고 실패 시에도 후보별 상태를 보고합니다.
자동 보고서에서 `not_started` 유형은 제외합니다.
`reviewed_unverified`는 단계가 실행됐다는 뜻이며 취약점 확정이나 방어 입증이 아닙니다.
HTTP 증거 수집기는 추가하지 않았습니다. 실제 탐지율·호출 효율 개선은 같은 조건의 비교 실험이 필요합니다.
변경 상세는 `prompts/system/CHANGELOG.md`에 기록합니다.

### 주요 파일

- `app.py`: FastAPI API와 실행 관리
- `explorer.py`: 브라우저 관찰, LLM 계획 실행, 가설 실험 및 응답 비교
- `model_providers.py`: OpenRouter 모델 목록, 설정 변환 및 스트리밍 어댑터
- `planning.py`: 계획 스키마, 모델 지시문, 결정 검증
- `j1_policy.py`: J1 관찰 참조·후보 단계 검사, 기준 코드 참조 보존, 컨텍스트 미리보기 압축
- `browser_http.py`: 대상 origin 검사, 기존 HTTP 도우미, 브라우저 폼 요청 재사용
- `lab.py`: 로컬 Juice Shop 컨테이너 상태 확인과 시작
- `static/`: 대시보드
- `tests/`: 테스트
- `Version/`: v1·v2 설계 문서

## 개발 상태

MVP 실험 단계입니다. 검색 입력은 연결된 레이블, 접근성 이름과 상위 검색 영역을 함께 읽어 인식하며, 숨겨지거나 접힌 입력은 선택지에서 제외합니다.
계획, 탐색 순서와 검색값은 LLM이 선택합니다. 실행기는 화면 상태별 실패·변화 없는 행동과 반복 전환을 제한하고 그 이유를 모델에 전달합니다. 같은 입력에서 다른 검색값은 선택할 수 있습니다.
실행할 수 없는 선택이 3회 연속 이어지면 `탐색 정체`로 종료하며, 모델 연결·응답 생성 오류는 별도로 표시합니다. 실행 데이터, 로그, 로컬 의존성은 Git 저장소에서 제외됩니다.
