# MVP v1 — 로컬 웹 탐색 에이전트

## 목표

Ollama의 `qwen3.5:2b`가 로컬 OWASP Juice Shop을 탐색하고, 사용자가 브라우저 대시보드에서 선택 이유, 실행 명령, 응답, 발견 경로를 볼 수 있게 한다.

## 범위

- 대상: `http://127.0.0.1:3000/` 한 곳
- 모델: 로컬 Ollama `qwen3.5:2b` (`http://127.0.0.1:11434`)
- 탐색: 읽기 전용 HTTP GET, 최대 20회, 요청당 8초 제한
- 발견: HTML 링크·스크립트·폼과 JavaScript에 나타난 경로 후보
- 화면: 시작·중지, 진행 상태, 실시간 Ollama 출력 콘솔, 모델 선택 이유, CMD에서 재현할 수 있는 명령, 응답 및 발견 목록
- 결과: 대시보드에서 JSON 다운로드

취약점 판정과 공격 명령은 v1 범위에 포함하지 않는다. 탐색기는 모델의 자유 형식 명령을 실행하지 않는다. 모델은 발견된 후보의 번호만 선택하고, 프로그램이 URL을 검사한 뒤 `curl.exe`를 셸을 거치지 않고 실행한다. 대시보드에는 CMD에서 재현할 수 있는 명령을 표시한다.

## 실행 흐름

1. Ollama와 Juice Shop의 연결 상태를 검사한다.
2. 시작 URL과 주요 JavaScript 파일을 요청해 후보 경로를 추출한다.
3. 미방문 후보와 최근 결과를 짧게 모델에 전달한다.
4. 모델은 `think:false`로 `visit`, 후보 번호, 선택 이유를 JSON으로 생성한다. 생성된 텍스트를 스트리밍해 화면에 바로 표시한다.
5. 프로그램은 대상 호스트와 요청 한도를 확인한 뒤 요청한다.
6. 결과를 기록하고 대시보드에 표시하며 후보가 없거나 20회에 도달할 때까지 반복한다.

모델 응답을 해석하지 못하면 한 번 재요청한 뒤, 남은 후보 중 하나를 규칙으로 선택하고 대체 선택임을 기록한다. JavaScript로 렌더링하는 화면은 HTTP 응답만으로 확인되지 않을 수 있으므로, 발견 후보와 응답으로 확인된 경로를 별도 상태로 표시한다. 다른 경로에서 시작 HTML이 그대로 돌아오는 경우도 확인된 경로로 세지 않는다.

## 대시보드

로컬 `http://127.0.0.1:8765/`에서 제공한다. 실행 상태, 단계 수, 확인된 경로 수, 후보 수, 오류 수를 표시한다. CMD 형태의 실시간 콘솔에는 Ollama의 생성 출력과 실행 명령 및 HTTP 결과를 Server-Sent Events로 표시한다. 여기 보이는 내용은 내부 `thinking`이 아니라 `think:false` 상태에서 생성된 선택 이유와 JSON이다. 시간순 기록에는 모델 선택 이유와 요청 명령, HTTP 상태, 응답 종류, 새 후보 수를 표시한다. 발견 목록에는 경로의 출처와 확인 상태를 표시한다. 시작·중지와 JSON 다운로드를 제공한다.

## 검증

- 20회 한도, 중지 버튼, 로컬 대상 제한이 실제로 작동해야 한다.
- 모든 실행 요청에 명령·응답·시간과 선택 이유가 남아야 한다.
- 에이전트에게 주지 않은 경로 목록 10개를 별도로 준비해 발견 수를 측정한다.
- HTTP 200만으로 경로를 인정하지 않고, 시작 HTML 재전송 및 잘못된 API 응답을 구분한다.
- 모델의 형식 오류, 중복 요청, 후보 대비 확인된 경로 수를 기록한다.

## 실행

백엔드는 FastAPI, ASGI 서버는 Uvicorn을 사용한다. Docker Desktop과 Juice Shop, Ollama가 실행 중인 상태에서 프로젝트 루트의 `run.cmd`를 실행하거나 `python app.py`를 실행한다. 브라우저에서 `http://127.0.0.1:8765/`을 연다. Python 패키지가 없다면 `python -m pip install -r requirements.txt`로 설치한다.
